# OctoAcme Project Management Docs

A central entry point for the project management practices used by OctoAcme. These documents describe how the team validates new work, plans delivery, manages risk, communicates status, executes on a project board, releases changes, and learns from each milestone.

OctoAcme follows a lightweight, iterative project lifecycle. New ideas begin with initiation: confirming the business need, aligning stakeholders, estimating scope and effort, and documenting a one-pager with goals, risks, and success measures. Approved work moves into planning, where the team creates a prioritized backlog, defines acceptance criteria, estimates effort, identifies dependencies, and agrees on milestones and a Definition of Done. During execution, work is tracked on a project board, progress is reviewed in standups and demos, and blockers are escalated as needed. Releases require readiness checks, deployment verification, and rollback planning. After each sprint, release, or milestone, the team captures lessons learned and turns them into improvement actions.

## Key practices

- Clear ownership: each project has a named Project Manager and Product Lead.
- Customer-first delivery: work is prioritized around customer value and measurable outcomes.
- Small, testable increments: changes are reviewed and validated before release.
- Regular communication: standups, weekly updates, demos, and stakeholder briefings keep teams aligned.
- Quality and safety: CI checks, testing, security scans, QA validation, and retrospectives support reliable delivery.

## How to use this repo

Use these documents as the working playbook for OctoAcme projects. Start with the overview and initiation guide for new efforts, then move into planning and execution docs as work progresses. Keep project artifacts updated in the repository and use the release and retrospective guidance to improve repeatability over time.
